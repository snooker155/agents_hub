# @agents-hub/sdk (TypeScript)

A typed client for talking to an Agents Hub from outside it, in TypeScript
or plain JavaScript: the dashboard's own `agents`, `tasks` and `chat`
routes, and the OpenAI-compatible `/v1` surface. See
[docs/sdk.md](../../docs/sdk.md) in the hub's own documentation corpus for
the full reference; this file is the quick version.

```bash
npm install ./clients/agents-hub-ts   # from this hub's repository
```

Not on npm yet, so it installs from the repository your hub came from, the
same way `clients/agents-hub-langgraph-js` does.

```ts
import { AgentsHub } from "@agents-hub/sdk";

const hub = new AgentsHub({ baseUrl: "http://localhost:8000", apiKey: "ahk_..." });

const agents = await hub.agents.list({ workspace: "shop" });
const { response } = await hub.chat.send({ agent_id: "support-bot", message: "Where is order 42?" });
```

`apiKey` is a personal API key (`ahk_...`, docs/api-keys.md) in
`AUTH_MODE=multi`, the shared `AGENTS_HUB_API_TOKEN` in `token` mode, or left
out in `single` mode. Sent as `Authorization: Bearer <apiKey>`.

## Layout

- `src/generated/types.ts`, `openapi.schema.json`: generated by
  `scripts/gen_ts_sdk.py` from the hub's own OpenAPI schema. Committed, so
  the package builds without a hub running. Regenerate with
  `npm run gen` (or `python3 ../../scripts/gen_ts_sdk.py` from the repo
  root); `python3 ../../scripts/gen_ts_sdk.py --check` fails if they are
  stale.
- `src/transport.ts`, `src/errors.ts`, `src/sse.ts`: the hand-written
  fetch wrapper, the one error type every failure maps to, and the SSE line
  reader both streaming calls use.
- `src/agents.ts`, `src/tasks.ts`, `src/chat.ts`, `src/v1.ts`: the ergonomic
  layer, one file per resource.
- `src/client.ts`, `src/index.ts`: the `AgentsHub` class and the package's
  public exports.
- `examples/widget/`: a page embedding the hub's chat widget, and a Node
  script calling an agent through this SDK instead.
- `test/`: `node --test` against the sources directly, with a small `fetch`
  double (`test/testing.ts`), no running hub required.

## Scripts

```bash
npm test         # node --test "test/*.test.ts"
npm run typecheck  # tsc --noEmit, strict
npm run gen       # regenerate the two generated files (needs Python, not Node)
```

## Requirements

Running the package's `.ts` files directly, as `npm test` and the examples
do, needs Node 22.18 or newer (native, unflagged type stripping) or a
bundler; there is no build step and nothing here that cannot also run
through `tsc`/esbuild/etc. if your own toolchain prefers that. The source is
plain TypeScript with no non-erasable syntax (no enums, no namespaces, no
parameter properties), so stripping it is all any of this needs.

Zero runtime dependencies: only the global `fetch` (Node 18+, or a browser).
`typescript` and `@types/node` are devDependencies, used only by
`typecheck` and by editors.
