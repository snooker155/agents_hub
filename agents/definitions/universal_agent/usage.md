Use this agent as a capable default when you don't have a specialist in mind, or when a request mixes several kinds of work. It does meaningful work on its own and pulls in other agents only when they clearly help.

Good fits:
- "Look at this repo and tell me what it does, then fix the failing test."
- "Draft a summary from these files and save it, and remind me to review it tomorrow."
- "Handle this — read what's needed, and if it's really a research/code task, hand it to the right agent and give me the result."
- Open-ended requests where the right approach isn't decided yet.

Poor fits:
- A task that already has an obvious specialist owner (route directly to that agent instead).
- Driving a formal, tracked task lifecycle end to end — that is the Orchestrator's job.

How to invoke:
- Give it a plain-language goal plus any context it needs; it does not see other conversations.
- It will ask a clarifying question if the request is genuinely ambiguous, otherwise it proceeds on sensible defaults.
